## 2. Kết luận phân tích (vì sao làm các việc ở mục 4)

1. **B5-EN lần 1 chưa so được với B3b-EN**: được đánh giá ở iter 4000 × batch 1 = 4000 mẫu (chọn theo mAP val), B3b-EN ở
   14000 mẫu. `iter_16000.pth` đã có → chỉ cần đánh giá (T0).
2. **Caption cho LLM là nút thắt**: ~40 từ (paper ~115), phần lớn là tên lớp + vị trí + thuộc tính chung của lớp (thứ loss
   grounding đã dạy); phần riêng của ảnh (cụm `extra` của Gemma, dịch máy) nhiễu và chưa ai duyệt. Paper Table 7: caption
   kém chi tiết / nhiều ảo giác làm mất 0.9–1.3 AP và tới 5.1 APr.
3. **Thiếu Step 1 của paper** (căn chỉnh connector trước khi train chung): loss LLM đầu B5-EN là 3.05 / 1.62.
4. Sai khác mAP giữa các mô hình EN ≤ 0.012 trên 414 ảnh, chưa có khoảng tin cậy → dùng bootstrap ghép cặp.
5. 5 lớp AP ≈ 0 và vài cặp giống hình kéo mAP nhiều hơn mức B5 có thể đem lại → `sessions/PROPOSAL_merge_classes.md`.

Quyết định của nhóm (12/11): caption sinh bằng **model cục bộ**; mục C9 sẽ **gộp lớp**, phạm vi chốt sau khi soát nhãn
(chưa áp dụng — xem cổng G1).

## 4. Việc cần làm trên server (theo thứ tự)

Quy ước: mỗi bước ghi "Xong khi"; bước train nào cũng chạy `SMOKE=1` trước nếu script có. Ghi log ra ổ local, không ghi ổ CIFS.
Sau mỗi bước: commit file kết quả `grounding_data/vifood54/EVAL_*.md` và thêm vài dòng vào session log.

### T0 — Chẩn đoán B5-EN lần 1 (không train, ~30 phút GPU)
```bash
git fetch && git checkout truong/b5-en-v2 && git pull
python scripts/vifood54/captions/test_caption_v2.py          # phải in 3 dòng "ok"
bash scripts/vifood54/run_phase0_b5_diag.sh
```
Xong khi có `EVAL_EN_B5LAST.md`, `EVAL_GROUNDING_EN_B5LAST.md`, `EVAL_GROUNDING_EN_VAL.md`. Đọc kết quả iter 16000:

| Kết quả | Nghĩa là | Tiếp |
| :--- | :--- | :--- |
| L2 R@1 ≈ 0.83, mAP ≈ B3b-EN | lần 1 chỉ là lỗi chọn checkpoint; LLM với caption hiện tại không hại, không lợi | làm tiếp như kế hoạch |
| L2 lên nhưng mAP giảm thêm | loss LLM kéo lệch detector | T5 (có bước căn chỉnh) càng cần; xem thêm T1b |
| L2 không lên | có lỗi ở nhánh VG của B5 | DỪNG, báo lại trước khi train gì thêm |

### T1 — Thống kê (CPU)
```bash
P=llmdet_vietnamese_food/work_dirs
python scripts/vifood54/analyze_eval.py --gt grounding_data/vifood54/annotations_en/instances_test.json \
  --pred B3b_EN=$P/vifood54_en_test_b3b/preds.pkl --pred B1_EN=$P/vifood54_en_test_b1/preds.pkl \
  --pred B5_EN_it4000=$P/vifood54_en_test_b5/preds.pkl --pred B5_EN_it16000=$P/vifood54_en_test_b5_last/preds.pkl \
  --baseline B3b_EN --bootstrap 1000 --out grounding_data/vifood54/EVAL_EN_PAIRED.md
```
T1b: đưa log train của B3b-EN và B5-EN vào git (`work_dirs/vifood54_b3b_ft_en/*/vis_data/scalars.json`,
`work_dirs/vifood54_b5_lmm_en/*/vis_data/scalars.json` → chép vào `grounding_data/vifood54/logs/`), so `grad_norm` và mAP val
theo cùng số mẫu. Nếu `grad_norm` của B5 lớn gấp nhiều lần B3b: báo lại (cần tách cắt gradient detector / LLM, chưa viết).

### G1 — Cổng: chốt gộp lớp (người quyết, không cần GPU)
Đọc `sessions/PROPOSAL_merge_classes.md`, soát nhãn các lớp nhóm A/C.
- **Nếu gộp**: làm 6 bước ở mục 4 của file đó (sinh lại dữ liệu, train lại B1-EN và B3b-EN) TRƯỚC T4–T8.
- **Nếu chưa chốt**: T2 và T3 (chạy thử 50 ảnh) làm trước được. T4 trở đi nên chờ, vì caption lấy tên món từ nhãn và mọi
  run sau đó phụ thuộc bộ nhãn; chạy trước rồi mới gộp thì phải làm lại.

### T2 — Nền LLMDet (~4 h GPU, nếu chưa có `EVAL_LLMDET_BASE_EN.md`)
```bash
bash scripts/vifood54/run_llmdet_base_en.sh
```
Nếu B1-L-EN > B1-EN (xem bảng so ghép cặp): báo lại để quyết định có chạy lại B3b-EN / B5 từ B1-L-EN.

### T3 — Caption v2, chạy thử 50 ảnh (GPU, môi trường có Gemma / LLaVA-OV)
```bash
M1=llava-hf/llava-onevision-qwen2-7b-ov-hf      # model mô tả (kiểm tra tên repo HF; có thể đổi sang model cục bộ khác)
M2=huggingface/gemma-4-12B-it                   # model kiểm chứng + dịch (phải KHÁC M1)
C=scripts/vifood54/captions/caption_v2.py
python $C describe --model $M1 --limit 50
python $C verify   --model $M2 --load-4bit
python $C compose && python $C stats
python $C translate --model $M2 --load-4bit
VIFOOD_LANG=en python scripts/vifood54/captions/review_captions.py --reviewer <tên> --port 7863
```
Người duyệt đọc bản Việt, ghi số câu sai. Ghi lại: s/ảnh từng bước, số từ trung bình, tỉ lệ chi tiết bị kiểm chứng loại,
số câu sai / caption. **Ngưỡng để chạy cả tập**: ≥ 70 từ trung bình, < 1 câu sai / 10 caption sau duyệt.
Không đạt: thử đổi vai M1 ↔ M2, hoặc dùng API (Gemini) cho bước `describe`; báo lại số liệu.
Lưu ý: script gọi VLM qua `AutoModelForImageTextToText` + chat template — chưa chạy thử trên GPU, lỗi nạp model sẽ hiện ngay ở ảnh đầu.

### T4 — Caption v2 cả tập train (3138 ảnh) + duyệt + gắn
```bash
python $C describe --model $M1 && python $C verify --model $M2 --load-4bit      # chạy lại được giữa chừng
python $C compose && python $C translate --model $M2 --load-4bit
VIFOOD_LANG=en python scripts/vifood54/captions/review_captions.py --reviewer <tên>   # ưu tiên: flagged → lớp hiếm / cặp dễ nhầm → 20% ngẫu nhiên
VIFOOD_LANG=en python scripts/vifood54/captions/vlm_captions.py attach --suffix _lmm_v2
```
**Luôn có `--suffix _lmm_v2`**: không có thì ghi đè `*_lmm.jsonl` (caption hiện tại, dùng cho B5a).


### T7 — B5b (caption v2; ~3 h GPU; cần T4)


### T8 — OV-W-EN (cần T4 + T6; ~0.5 h + 3 h, ablation thêm ~3 h)
```bash
VIFOOD_LANG=en python scripts/vifood54/captions/vlm_captions.py attach --ov
bash scripts/vifood54/run_ov_en.sh w
```

`attach --ov` phải báo nguồn caption chủ yếu là `vlm` (caption v2). Nếu chủ yếu `template_L2` thì caption không có tên novel
→ thí nghiệm vô nghĩa, quay lại T4. Smoke lỗi ở ảnh không có box: đặt `keep_empty=True` trong `..._ov_s2_lmm.py` và báo lại.
